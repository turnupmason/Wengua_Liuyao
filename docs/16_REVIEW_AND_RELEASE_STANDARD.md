# 16 研究、审核与发布规范（长期，依用户指令 V3.0，2026-11-13）

> 本规范对全部现存与今后的六爻断语一律适用。已批准稿件如发现违反本规范，须重新复核，不因历史批准状态保留错误。规则争议的用户裁定见 `rules/register.json`（disputes 中 status=ruled 与 rulings）。

## 一、研究授权与证据标准

- 用户授权在规则审核、断语编写、复算与润色中充分联网检索，不限于仓库现有古籍。
- 网上说法只用于发现资料与交叉核对；规则成立须以可核实的原文（书名、作者、版本、篇章、原文）与完整课盘事实为据。现代网文不得冒充古籍原文；后世解释不得说成某书统一标准；版本异文须保留差异与采用理由。
- 每批断语开工前扫描现有知识库：`sources/classics/`、`sources/manifest.json`、`rules/register.json`（规则、分歧、裁定）、`rules/collation.json`、`docs/01–15`、`authoring/`（含 history）、`review/records.json`、`reports/`。每条正式判断须能追溯到所用规则版本。
- 「全面查阅」指系统检索全部可获得且相关的资料并记录检索范围与未覆盖部分，不得宣称读完全部古籍。

## 二、六个审核角色

| 角色 | 职责 | 记录 stage |
|---|---|---|
| AI-1 专业作者 | 依确定性排盘事实、已批准规则与古籍，先写结构化判断（judgment，含 decisive 主要依据爻）再写正文；按审核证据修订 | `ai-author` / `author-full-text-review` |
| AI-2 古籍校勘 | 独立核对全部引文：是否存在、是否完整、是否断章取义、版本、适用条件、例外、相反论述、编号对应；必要时联网对照他本 | `ai-source-check` |
| AI-3 独立复算 | 不看作者结论，凭排盘事实与规则独立断案，再比较用神、旺衰、动化、伏神、证据与结论；分歧须指出具体规则与条件 | `ai-independent` |
| AI-4 反向质疑 | 主动找漏洞：轻放的凶证或吉证、月令休囚误判、生扶重复累计、空破动化伏神遗漏、静爻当动、接续相生未审、只取一句警语、现实化表述、事实不一致、应期无据、套话 | `ai-adversarial` |
| AI-5 中文精修 | 只改表达，不改吉凶、事实、条件、反证、应期含义与古籍取义 | `ai-editor` |
| AI-6 最终验收 | 重新检查专业判断、来源、文字、排版、适用条件、数据状态，逐项核对第四节 17 条 | `ai-final-qa`（须绑定最终内容哈希） |

运行环境支持独立代理时，AI-2、AI-3、AI-4、AI-6 以隔离上下文的独立代理执行；AI-3 以指令禁止读取作者稿（文件系统共享，记录中如实注明）。只有一个模型时，须在不同阶段重新读取原始事实独立判断，不得虚称由不同模型审核。

## 三、流程

起草（AI-1）→ 古籍核查（AI-2）→ 独立复算（AI-3）→ 反向审查（AI-4）→ 专业修订（AI-1）→ 中文精修（AI-5）→ 终审（AI-6）→ 技术回归（构建与全部测试）。有明确缺陷则退回相应阶段。不设「改三次即通过」；不得反复调用 AI 直到出现满意答案；每次实质修改后重查专业判断；无法裁决的规则争议保持待核。

审核顺序固定：排盘正确 → 用神正确 → 日月正确 → 动变正确 → 特殊规则正确 → 古籍正确 → 判断有据 → 文字精修 → 最终批准。证据优先，不以多数票定吉凶：AI 之间结论不同，须找出分歧的具体规则或条件并重新复算。

## 四、发布条件（全部满足才 AI_APPROVED）

`scripts/lib/review-status.mjs` 的 `RELEASE_CONDITIONS`：排盘与计算测试全部通过；所用规则已经批准；用神选择有明确依据；正反证据均得到处理；没有未解决的重大专业冲突；关键古籍引用已经核查；应期有适用依据或明确记录不适合取期；独立专业审核完成；反向质疑审核完成；最终语言编辑完成；没有明显机械重复、套话或病句；简断、详断、总断结论一致；原有正式排版完整保留；内容哈希、规则版本及审核记录一致；全部相关回归测试通过；无未经证实的现实事实断言；没有冒充真人专家认证或现实预测保证。

- 全部满足：`approval_status = AI_APPROVED`，`production_allowed = true`；否则 `REVIEW_REQUIRED`，`production_allowed = false`。
- 构建技术检查（C03–C26）任一失败，即使有审核记录也降为 REVIEW_REQUIRED。
- 「所用规则已经批准」的口径：规则须为用户裁定，或经 AI-2 原文核验通过（register `review_status: ai-verified`），且不涉及未裁定的分歧。AI 核验批准不是人工专家认证，报告中须分开写。
- 人工路径（professional-review + release-approval，非 AI 审核者）仍有效，记为 HUMAN_APPROVED。

## 五、计算事实

六十四卦、八宫、纳甲、世应、六亲、六神、动变、月建、日干支（0 时换日，D-009）、旬空、月破、日冲日合、飞伏、进退神、回头生克、刑冲合害、检索条件，一律由确定性程序计算并以独立算法或古籍卦例交叉核对，穷举基础组合测试。发现计算错误：暂停受影响内容发布，修源头，回归全部受影响断语。百分之百指可验证事实与审核覆盖，不指预测应验。

## 六、写作

- 禁止模板化、机械重复、AI 腔与术语堆砌；第六节所列套话由构建检查 C23 拦截；篇内重复句 C24；跨篇字符六元组相似度 C25（>0.30 须复核）；跨篇 14 字以上同句 C14。真正等价且审核过的情境可共用正文，不同条件不得用重复正文掩盖区别。
- 绘声绘色但不编造：不得写对方已决定、内部有人支持、已发通知、必有下一轮、某人必得岗位等未经证实的现实事件；可依传统象意作有条件的解释。
- 专业判断转为自然语言：讲清条件之间的关系与因果，不罗列事实。
- 古籍引用须真正支持断语：求名专章、一般生克、元神忌神衰旺章、飞伏神章、旬空章之间须综合（如「子孙持世，休望荣荫」须看忌神实际旺衰发动，D-016）。

## 七、排版

正式稿依次为：编号与标题、问事、卦盘、月建日辰旬空、匹配键与审核状态、六爻排盘、简断、详断·开局、详断·过程、详断·结局、应期、总断、古籍依据、计算说明。构建检查 C26 校验栏目齐全与次序；结构标题与正文分开（C19），不得出现「总断：总断」。技术元数据与计算说明独立存储，用户正文不含审核过程。

## 八、每轮质量报告

本轮实际编写篇数；查阅的古籍章节与版本；联网核对的争议与网址；使用的知识库资料；核验成功与无法取得的原文；规则分歧（已解决/待核）；计算测试通过数；AI 独立审核通过数；反向审核退回数；精修完成数；重复文案修复数；正式批准数（AI_APPROVED / HUMAN_APPROVED 分列）；未批准数；剩余问题；下一批工作范围。不得把检索到的来源数冒充阅读数，不得把 AI 审核冒充真人专家审核，不得把自动计算通过冒充断法正确，不得把预写正文数冒充已发布数。报告存于 `reports/`。
