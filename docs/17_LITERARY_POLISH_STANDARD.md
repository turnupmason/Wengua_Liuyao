# 17 文学润色标准（长期，依用户指令 V5.0，2026-11-13）

> 用户原文逐字存档：`docs/standards/V5.0_LITERARY_POLISH_INSTRUCTION.md`。本文件只写它在本仓库里的执行口径。两者不一致时以原文为准。

## 一、定位

- 润色只做语言编辑，不做专业裁决：不重新排盘、不重选用神、不改吉凶、不改应期、不改古籍。
- 由一个 Claude 完成全部润色（V5.0 第十四节），**取消多 AI 文学审核**。docs/16 中「AI-5 中文精修」一环改由这一次润色完成；专业审核的各个环节（AI-2 古籍核查、AI-3 独立复算、AI-4 反向质疑、AI-6 终审）不受影响，V5.0 不涉及它们。
- 原稿本来就好，保留原稿也是合格结果（A 类）。不以改动数量衡量工作量，不为降低相似度制造虚假差异。

## 二、作者源字段：哪些能改，哪些锁定

权威作者源是 `authoring/interview-pass/*.json`。润色只改作者源，再重新构建；不得只改 `docs/11`、`data/release/`、`dist/` 等构建产物。

| 字段 | 润色时 |
|---|---|
| `reading.title` | 可改措辞；成败方向必须不变 |
| `reading.brief` | 可改；约 60–120 字；直接回答、说出关键原因 |
| `reading.opening` / `process` / `ending` | 可改；所述专业关系、条件、旺衰、动化不得增删或改变 |
| `reading.timing.text` | 只改生硬文字；地支、事件性质、吉凶、取期节点、规则依据不变 |
| `reading.conclusion` | 可改；结论不变，不与简断逐字重复，不用通用固定结尾 |
| `reading.timing.entries` | **锁定** |
| `reading.classical_sources` | **锁定**（只允许修正明显的显示排版问题） |
| `reading.calculation_explanation` | **锁定**（不属于润色范围） |
| `judgment`（全部子字段）、`chart_input`、`question_id`、`scenario_tags` | **锁定** |
| 排版（栏目顺序、名称、六爻盘自上而下、字段顺序） | **锁定**；由构建生成，检查 C26 守住 |

正文栏目顺序固定为：简断 → 详断·开局 → 详断·过程 → 详断·结局 → 应期 → 总断 → 古籍依据 → 计算说明。正文里不得再写栏目名（如「总断：」）。

## 三、写作要求（摘要，详见原文第三至第八节）

- 像专业老师向普通人解释：主要情况、有利之处、真正的担忧、可能变化的原因、最终倾向。
- 术语保留且准确，但不排成计算清单；语言解释卦理，不代替卦理，不添加原稿没有的判断。
- 不编现实情节，比如面试官的态度、公司内部的决定、竞争者的情况，也不写「一定能」这类话。
- 消除原文第四节列出的套话，也不能换成同义套话。每篇的语言特点应来自该篇自己的证据。
- 处理篇内重复：简断与总断不雷同；同一关系、同一建议不反复解释。
- 跨篇重复检测：可用 N-gram、SimHash、MinHash、语义相似度和重复短语统计（现有检查 C25 即 6-gram 相似度）。这些工具只用来发现问题。经审核的等价判断可以共用正文。

## 四、六遍流程

1. 读原稿，确认最终判断与关键证据。
2. 标出病句、重复、套话、术语堆砌、衔接不畅。
3. 只改确有问题的文字，并把原稿归为 A 类（不改）、B 类（局部改）或 C 类（整体重组）。
4. 逐句对照：专业事实、判断条件、吉凶、应期、古籍均未变。
5. 以普通读者身份通读。
6. 检查排版：重新构建后所有构建检查必须通过。

## 五、记录与状态

- 每篇润色在 `review/records.json` 追加一条 `stage: "polish"` 记录，`status: "POLISH_COMPLETED"`。记录须包含：
  - 案例 ID、question_id；
  - 原稿分类（A/B/C）与改动字段；
  - 每个改动字段的原文与新文（或差异）；
  - 原始结论；
  - 原内容哈希、新内容哈希；
  - 润色时间。
- 原稿另存为 `authoring/history/interview-pass/<ID>.r<N>.json`，可以随时还原。
- `POLISH_COMPLETED` 只表示语言润色完成，**不替代** `AI_APPROVED`，也不改变专业审核状态。专业待审的稿件润色后仍然待审。
- 文学润色与专业审核分开记录。发布条件「最终语言编辑完成」可由这条润色记录满足。
- 已批准的稿件润色后内容哈希会变。按 V5.0 第十五节，「仍须遵守现有版本及发布校验制度」。现行制度要求新哈希上有 AI-6 终审记录，才能保持 AI_APPROVED。因此在新哈希通过终审之前，该稿按 REVIEW_REQUIRED 处理，不进入发布包。

## 六、发现专业问题时

润色中如果发现某句话可能与专业事实矛盾，就单独记录（写在润色记录的 `professional_issues` 中），转专业审核处理，不在润色中擅改卦象、用神、动化、吉凶和应期。
