# 10 统一断语结构与写作质量

## 一、作者源稿结构（`authoring/<问事>/<script_id>.json`）

| 部分 | 要求 |
|---|---|
| `chart_input` | 六爻值（初→上）、月建、日辰。匹配键 = 问事 + 六爻值 + 月建 + 日辰 |
| `judgment` | 先写判断再写文字：结论类别（likely-pass / pass-but-slow / wait-then-likely / unlikely）、用神位置、决定性证据、支持证据、反面证据、冲突取舍、规则编号 |
| 标题 | 直接回答所问，体现本卦核心特点；不得写「吉凶参半」「事有变化」 |
| 简断 | 60–120 个汉字；主要倾向、最关键的帮助或阻碍、后续变化、一条现实建议；不堆术语（术语 ≥3 个给出提示），不写日期 |
| 详断·开局 | 用神、世应与日月条件：为什么目前是这个状况 |
| 详断·过程 | 动爻、原神、忌神、飞伏等真正影响本问题的证据；围绕证据组织，不逐爻机械讲 |
| 详断·结局 | 用神最终状态与关键条件，说明有利条件是否足以克服阻碍 |
| 应期 | 独立一栏，见 09 |
| 总断 | 明确结论 + 最关键依据 + 行动建议 |
| 古籍依据 | 每条：规则编号、书、卷章、逐字引文、本次适用理由 |
| 计算说明 | 专业事实，用户需要时才展开；构建另附引擎生成的卦盘事实表 |

## 二、文风

像一位懂六爻的老师在讲：语气平实、句子流畅、结论直接、证据清楚。每个术语第一次出现时说明它在这个问题里意味着什么（例如「旬空的意思是『此刻不在』」「子孙在求职卦里是克官之神」）。

严禁单独以下列句式构成解释：「用神旺，所以吉」「忌神克，所以凶」「存在一定帮助，但仍有阻碍」「综合各项因素，情况比较复杂」「按规则加权计算」「这里不能重复叠加」「模型认为」「源力待核」「这一项取最高评分」，以及「还要综合考虑」一类逃避结论的套话。构建脚本对这些短语与「程序、算法、引擎、概率、保证、百分之、R-」等内部用语一律拦截（C06）。

不得虚构：已发生的现实事件、对方真实心理、人物身份、具体金额、已确定的录用结果、具体地点、成功概率、古籍案例反馈。象意推断须带「从卦象看」之类的限定（IP-0006 自查记录）。

## 三、自动检查（`npm run build:readings`）

C03 用神与引擎一致；C04 必填；C05 简断字数；C06 禁用语；C07 简断无日期；C08 无公历日期；C09 正文中的「某日」只能是起卦日；C10 应期地支在规则候选内、说明与条目一一对应；C11 标题、简断、总断与结论类别一致且无相反措辞；C12 古籍引文逐字核对、规则已登记、写明适用理由；C13 每个动爻在详断中讲到；C14 跨篇不得有 14 字以上的重复句；C15 判断引用的规则已登记；C16 简断术语密度提示；C17 判别流程（飞伏、旬空、月日相敌、动化）逐项确认，伏神判为有用或并见时正文不得写「引不出」一类结论；C18 用神旬空而本旬内有冲空之日时，应期须列出该日，正文不得写「本旬之内不会有结果」；C19 正文不得以「总断：」等结构标题开头（结构标题由界面显示）；C20 不得出现超出回答范围的词（面试一问不写「录用」「Offer」）；C21 不得把对方态度、竞争情况写成定论（如「对方也在托举」「没有构成竞争压力」，应写「应爻财生世，传统上属于配合之象」「兄弟爻未见明显发动牵制」）。

技术检查全部通过只记为「技术核验通过」，不等于专业审核。

## 四、写作基准

用户第一轮复核选 IP-0003（雷地豫之泽雷随）为文风基准候选：先找用神并说明日月对它的影响，再讲推动力量从哪里来，再讲后势，同时处理反面条件，最后明确回答而不保证现实结果。其引文与应期已在第二轮复核（删去不适用的「官临日月必超迁」），仍待专业确认。

## 四之二、面试问断语细节（第三版，2026-11-15）

用户要求：断语要更细，涉及的范围要更全，不能泛泛而谈，要说细节。外部卦例的原断者都逐层讲：面试表现、能否录取、对方怎么看、有没有竞争、待遇如何、最后去不去，再加六神象意和应期。以后每篇面试断语按下表逐项写；某一项卦中无象时，写一句「这一层卦中没有明显的象」，不得略去。

| 项 | 看哪里 | 写什么（举例） |
|---|---|---|
| 1. 临场表现 | 父母的旺衰、动变（R-QIUMING-05、06） | 父化进神：越答越顺；父月破：笔试、材料吃亏；父化回头克：平时准备足，临场失利 |
| 2. 能否录取 | 官的旺衰，官与世的关系（R-QIUMING-08） | 旺官持世：位置在你手里；官衰父发：表现好，可以被取 |
| 3. 自身状态 | 世爻旺衰、受克与扶（R-QIUMING-11） | 世受日克而应爻生合：自己有短板，但有人帮衬 |
| 4. 对方态度 | 应爻与世的生克合冲（R-QIUMING-09） | 应合世：从卦象看，对方有意；应克世：对方要求严，或压价 |
| 5. 竞争 | 兄弟持世、兄动、兄局（R-QIUMING-12） | 兄动而被制：有竞争者，但压不过你 |
| 6. 待遇、条件 | 妻财旺衰、空伏、动静 | 财伏不出：待遇一时谈不上去（象意，带限定语） |
| 7. 去留 | 子孙持世、玄武、化空、入墓（R-QIUMING-10） | 子孙持世而父发：能被取，自己未必去 |
| 8. 象意细节 | 世、官、父、动爻所临六神；禄神、将星、驿马、贵人落在这几爻时 | 官临青龙：岗位体面；动兄临玄武：有人暗中竞争 |
| 9. 应期 | 通知看父母（R-QIUMING-16），录取看官（docs/09） | 两者不同时分开列 |
| 10. 建议 | 针对最弱的一层 | 父弱就补材料、练表达；应克世就谈薪留余地 |

写法要求：

- 每句判断都要落在具体的爻上：哪一爻、什么地支、临什么六神、受什么生克。不得只写「过程有压力」「整体不错」这类没有出处的话。
- 象意（六神、神煞、对方心意、待遇）一律带「从卦象看」之类的限定，并守 C21；不得写成已发生的事实。
- 等价类的正文对类内每一卦都要成立。六神随日干变化，类键里没有它，所以第 8 项不写进类稿，而由构建时按每一卦的排盘事实生成「本卦象意」一段（待实现，见 docs/18 第〇〇节与 `reports/interview-v3-review-2026-11-15.md`）。
- C20 修订（随 eq-0.14 构建检查一起改）：第三版分层回答，「录取」一层可以写「被录取」「录用」，但不得写成已确定的结果，也不写「Offer」。

## 五、状态与审核

1. 已完成基础事实（构建可重算）→ 2. 作者初稿（`authoring.status = draft-complete`）→ 3. 作者全文复核（`review/records.json` 中 `author-full-text-review`）→ 4. 技术核验（构建自动）→ 5. 专业规则审核（`professional-review`，审核者不得为 AI）→ 6. 发布批准（`release-approval`，须先有专业审核）。

记录绑定 `content_hash`：改稿后旧记录自动失效。发现矛盾时先记录问题、独立复算、确认规则、确定结论，最后改文字；不得先改结论再找卦理。
