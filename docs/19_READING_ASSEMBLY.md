# 19 断语库与类稿拼装（2026-11-16，依用户指令）

用户：「一个一个写完全不可能，你要想办法」「把他们总共用的断语写好，可以随时调用」「每个重要的东西还是要区分出来分开写」「别忘了最后润色 AI 需要润色的，保证完美极致」。

## 一、目标

类稿（每个等价类一篇：标题、简断、开局、过程、结局、应期、总断、古籍依据）不再逐篇手写，改由**断语库**拼装：

- 人只写断语库，以及改少数拼不通的稿；
- 拼出的稿一律走单 Claude 润色（docs/17 六遍流程）与终审；
- 先做工作领域第一组：求职录用（`career.interview.interview-pass`）、考试选拔、能否转正。

规模（类序 eq-0.14，2026-11-16 重排）：

- 覆盖一成起卦须 1113 类，两成须 4590 类；
- 前 4590 类只用到 54 个依据码；
- 类键其余部分由用神、世、原、忌、官世之情、三合局、卦级七种片段组合而成，每种几到几十个取值。

所以库按片段写，约一百几十段即可拼出前两成起卦的全部类；每加一个问事，只多写该问事不同的那几段。

## 二、断语库的组成（`authoring/library/<领域>/`）

1. **问事词表 `questions.json`**：每个问事一项，写明以下各条。凡问事之间要紧的不同，都由这里或下面两项的「分问事改写」接住：
   - 问事名、所问之事的说法（面试 / 考试 / 转正）；
   - 成败词（录取 / 上榜 / 转正）；
   - 用神及其在本问的意义，主用、辅看各几爻；
   - 回答范围、禁用词；
   - 应期所指（出结果 / 发榜 / 转正手续）；
   - 判定口径（interview / written / probation）。
2. **依据码段 `codes.json`**：每个否决、能过、分层码一项（如「否子动克官」「过旺官持世」「层世化子孙」），每项包括：
   - `short`：标题与「关键在」用的短语；
   - `body`：过程或结局用的一段解释：落到哪一爻、什么生克、古籍怎么说；
   - `advice`：针对这一层的现实建议；
   - `adv`：反方质疑与驳回；
   - `rules`、`quotes`：规则号与逐字引文的出处号，引文从 `rules/register.json` 原文取，不另抄；
   - `per_question`：意思不同的问事，在这里单独写一段，覆盖上面各项。只换问事名词的，不必单写，由词表替换。
3. **片段段 `segments.json`**：类键每种片段的每个取值各一项，写它在开局或过程里的那一句或两句，比如：
   - 「用明现持世[EFFECTIVE]静」「世受克」「原伏难出」「忌静旺有力」「官无情」「局子孙局待凶克世」「六冲」；
   - 片段由几个小部分组合的（用神的来源 × 位置 × 状态 × 动静），按小部分分写、程序组句，不为每个组合各写一遍。
4. **结论段 `verdicts.json`**：结论（能过 / 待时 / 偏难）× 问事的标题前缀、总断句式，以及按最弱一层选的建议。每种写两三种措辞，按类键稳定选取，避免跨篇雷同。

## 三、拼装规则（`scripts/authoring/assemble.py`）

输入：问事 + 类键（另读该类画像，取样本盘与类内变化）。输出：与现行 `make_class` 同一格式的稿件，交现有收尾与检查流程。

| 栏目 | 拼法 |
|---|---|
| 标题 | 结论前缀 +「主依据」短语。主依据按 `VETO_ORDER` / `PASS_ORDER` 取第一条；成败方向与第三版结论一致 |
| 简断 | 结论 + 主依据一句 + 次要的有利或不利一句 + 建议；60–120 字（C05 核） |
| 开局 | 用神片段（位置、旺衰、日月）→ 世爻片段 → 官世之情 |
| 过程 | 原神、忌神、三合局、动变、卦级片段 → 其余否决与能过各码的 `body`，按主次排列 |
| 结局 | 主依据 `body` 的结论句 + 有利条件是否足以克服阻碍 |
| 应期 | 沿用现行生成（按问事的应期所指换说法） |
| 总断 | 结论段句式 + 最关键依据 + 建议；不与简断逐字重复 |
| 古籍依据 | 所用各段 `quotes` 的并集，逐字取自 register，按书卷排 |
| 判断字段 | 结论、决定性证据、支持、反面、冲突取舍，由第三版签名与片段自动生成；`v3` 依据须覆盖签名里每个码（make_class 已有此核） |

主次（docs/17 第七节）：先讲决定结论的一两条，再讲被化解的条件为什么不算，最后讲细节。一条不漏：签名里的每个码都要出现在正文里。

## 四、去雷同与通顺

- 每段写两三种措辞，按类键哈希稳定选，同一类每次拼出的稿相同。
- 跨篇 6-gram 相似度（C25）照旧检查。docs/17 允许「经审核的等价判断共用正文」，但同一结论、不同依据的稿，不得读起来一样。
- 段与段之间的衔接词（「再看」「不过」「所以」）由拼装程序按前后段的吉凶方向选，不写死在段里。

## 四之二、不许有模板味（用户 2026-11-16：「确保看的没有任何模板味儿，这就是为什么我们最后需要润色的原因，而且也可以检查」）

拼装只保证事实与依据对。读起来像人写的，靠两道关：

1. **模板味检查（`scripts/authoring/template_smell.py`，润色前后各跑一次）**：在同一问事的全部类稿中统计以下各项。超阈值的句、段列出来，交润色时逐处改：
   - **跨篇重复句**：同一句（去掉地支、六亲后）在多篇里原样出现。
   - **跨篇重复段首**：多篇同栏目以同样几个字开头，如篇篇「这一卦」「先看」。
   - **固定句式**：「X，所以 Y」「虽然 X，但 Y」「从卦象看」等，在一篇或全体中的密度。
   - **衔接词扎堆**：「再看」「不过」「所以」等在一篇里的次数。
   - **跨篇相似度**：同栏目跨篇的 6-gram、SimHash 相似度。只要依据不同的两篇读起来高度相似，就算模板味。
   - **篇内重复**：同一关系、同一建议在一篇内说了两遍；简断与总断雷同。
2. **润色专门去模板味**：在 docs/17 六遍流程上加一条硬要求，每篇都按本篇自己的证据重新组织语言：
   - 句子长短、先后、衔接，跟着证据的主次走，不跟着段落的拼接顺序走；
   - 拼接痕迹（生硬的「再看」、段与段之间的重复交代）一律抹平；
   - 每篇至少有一两句只属于这一篇的话，比如这一卦独有的组合怎么相互作用。
3. **润色也是一道检查**：润色时逐句对照判断字段与卦盘事实，确认结论、依据、引文、应期节点都没变。
   - 发现拼装错误（段与类键不符、两段互相矛盾、主次颠倒），记入拼装问题清单，回去改库，不在单篇里将就；
   - 改库后重新拼装，受影响的稿重新润色。
4. **润色后复跑模板味检查**：
   - 所有超阈值项要么已改掉，要么逐条注明为什么不必改（如古籍引文本身相同）；
   - 复跑结果与润色记录（A / B / C 类）一起存档，终审时一并看。

## 五、质量门

1. 拼装时自检：
   - 签名各码都有段；
   - 片段取值都有段；缺段的类不出稿，记入缺段清单；
   - 「拼不通」组合表里的类标出来，转人工。
2. 现有构建检查（C01–C26）全过。
3. 样本盘逐盘核对：类键决定的事实对样本每一盘都成立（现有 class-samples 检查）。
4. **单 Claude 润色**（docs/17 六遍流程）：
   - 每篇读全文，只改措辞，不动结论、依据、引文、应期节点；
   - 记 A / B / C 类；
   - 润色中发现规则断不通的，不改结论，记入专业问题。
5. 终审（docs/16 AI-6），记录绑定内容哈希。

## 八、试点结果与定下的流程（2026-11-16，面试一问前 36 类）

试点报告见 `reports/assembly-pilot-interview.md`。

1. **库的实际形态**：库写成 Python 数据（`scripts/authoring/library/career.py`），不分四个 JSON 文件；拼装程序 `scripts/authoring/assemble.py`。类键片段之外，还取画像中全类一致的事实（月建六亲、用神月令、世爻六亲、三版父层、全类皆有的加分减分与象注），这一部分是类与类之间真正的区别，库里按条写（`PM`）。
2. **骨架不能直接发布**：构建检查 C14 不许 14 字以上的句子跨篇重复；前 36 类的骨架跨篇同句 204 处。所以拼装只出事实骨架，**每篇必经润色改写**；程序上，未润色的拼装稿不写稿（`assemble.py write` 只写有润色稿的类，`--raw` 仅供调试）。
3. **润色稿单存**：`authoring/polish/<问事>/P-<名次>.json`，按类键对应，只含正文各栏、标签、反方与依据码原句（`v3`）；判断字段、引文、应期仍由拼装生成，润色改不动。拼装时核对润色稿的依据码与签名一致、每条原句确在正文。
4. **每批的顺序**：拼装骨架 → 逐篇润色（对照画像逐句核事实）→ `assemble.py write` → 构建检查与出处、引文、读者视角各项审计 → `template_smell.py --ids …` 零项 → `finalize_batch.py … --note …` 记润色与终审 → 测试、规则核对。
5. **润色兼作检查**：试点中查出骨架与库的错误（出处章名错 2 处、序言误作用神章 1 处、无码待定类结局引文对全类不成立 1 处、世爻六亲不一时缺主语），已回改库；润色中查出对全类不尽成立的说法 6 处，已改。
6. **原 30 篇手写稿的模板味**：简断多以「这一卦倾向通过 / 偏难」开头，「这一卦」一篇用三到五次等；待批量润色时一并复润（改后须重记终审）。

## 九、手写稿复润与错字防线（2026-11-16）

用户：「所有断语不能有重复明显的模板，句子过度使用，坚决不能有任何错别字。」

1. **原 30 篇手写稿复润**：复润稿存 `authoring/polish/interview/P-<名次>.json`（`base: handwritten`），由 `make_class.make` 套在原批次稿上，只换正文措辞；依据码原句只在须去掉对读者的内部用语（「第三版判……」）时改。润色记录按 B 类逐栏记前后文本；`record-polish.mjs` 把 `judgment.v3_basis[].text` 作可润色字段（它只是正文那句话的指针），判断其余部分仍锁定。
2. **错字的来源**：31 篇「后一般落空」不是写稿时打错，而是读者视角转换（`reader_voice.py`）把一切「一半」机械改成「一般」。已改为比例词须带「盘」才算类内统计；全部 334 段正文比对，只此一处受影响。
3. **检查加项**（`template_smell.py`）：引文外的古籍标点、半角标点、引号不配对、标点连用、可疑叠字、已见错字表；简断与总断开头分散、「这一卦」叠用、跨篇 8–13 字同句。
4. **机器之外必须逐字通读**：本轮 40 篇定稿逐字通读，另查出内部用语「本类」2 处、缺动词 1 处、量词误用 1 处、篇内重复 1 处、标题措辞过重 1 处，均已改。以后每批润色后都须逐字通读，不以检查脚本零项代替。
5. **动变用语**：类稿正文只写全类每一卦都成立的事实；回头生、回头克、化进退、化绝化墓等动变在这些类里都只见于部分卦，由逐卦断语段（`interview-v3-text.js`）按该卦逐条写出（已抽样核对）。用神本身动化的类（类键用神段带化凶、化吉、化退旺、动平）尚未进库，拼装程序遇到即报缺段，铺开前须先写这些段。
6. **世应**（用户：「还有世应这些」）：40 篇逐类核对，世应关系全类一致而正文未写者 4 类（31、35 比和，147 相合，1531 世克应而相合），已补。库加 `SHIYING`、`SHIYING_ADD`，拼装时取类内每一卦都相同的世应关系写进过程段（官临应者已在官星句中交代；应克世已由全类减分句交代者不重写）。类内各卦不同的世应生克冲合，由逐卦断语段写出。
7. **引擎判了什么都要写出来**（用户：「确保你引擎断了什么，都要在模板里体现出来」）：两层核对。
   - 逐卦断语：`scripts/analysis/audit-v3-text-coverage.mjs`，随机 2 万盘，判断条目 446 种全部写进；查出六冲变六合下被压下之否决的转折句被「判断依据」前 8 字比对吞掉，已改（逐卦断语 1.2.1）。
   - 类稿：`scripts/analysis/audit-class-coverage.py`，全类每卦皆判到之条目（加分、减分、象注、用神与世爻之空破伤损动化）须写进正文，按标记词核；首次核出 32 处缺写（官出现旺相「为久为远」22 篇等），已逐篇补写；97 篇标题「伏在你世下」非全类皆然，已改。两项都进了 run_batch_checks.sh。
8. **逐卦断语去清单**（用户：「这个『判断依据』你要想办法，既不能过度模板说话，还要引擎断了什么，用了什么规则，所有都要写出来」）：逐卦断语 1.3.0 起，加分、减分、能过与上文未写到的象注、否决，不再以「加分：」「减分：」「有利：」清单或「判断依据」兜底段列出，而由 `weave()` 按所论之爻归段（父母→临场表现，官鬼与子孙→能否录取，世、日辰合世、动爻墓世→自身状态，应、世应→对方态度，兄弟与间爻兄弟→竞争，妻财→待遇，克父者归临场表现，卦宫与六冲六合→卦象，神煞→象意），古籍原句以「」嵌入，「火珠林：」「谒贵：」等出处标签写成「某某说」，「只作象，不计加减」等内部说明改为「只作卦象参看，不左右成败」，并按吉凶写明于你有利或不利。2 万盘核对：兜底与清单 0 条，446 种条目全部写进。对照见 `reports/v3-text-weave-sample.md`。措辞的最后一道仍是逐案润色。
